# PR 3 — Power Automate Outlook webhook provider

Commit:

```text
feat(power-automate): add Outlook webhook provider
```

Goal: invoke a configured Power Automate HTTP trigger. The flow uses the Office
365 Outlook connector's shared-mailbox send action and owns the temporary user
connection.

Add:

```text
src/notification_service/power_automate.py
```

Construct it in the upstream application:

```python
from notification_service import PowerAutomateEmailProvider

provider = PowerAutomateEmailProvider(
    flow_webhook_url,
    authorization_token=user_access_token,  # temporary authentication
)
client = NotificationClient(provider)
```

The payload includes recipients, subject/body, correlation ID, idempotency key,
and base64 attachments. The flow must return a documented response. A successful
HTTP response means the trigger/flow accepted the request, not confirmed email
delivery.

Required flow contract:

1. Require authenticated callers or protect the trigger URL in the host secret store.
2. Validate `schema_version`, recipient domains, attachment count, and sizes.
3. Use **Send an email from a shared mailbox (V2)**.
4. Disable connector retries or make the flow deduplicate by `idempotency_key`.
5. Return JSON containing an optional `run_id` or `message_id`.

Do not log the webhook URL, bearer token, request body, or attachment content.
Replace the user connection with an Entra service identity later; no caller API
change is required.
