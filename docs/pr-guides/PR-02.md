# PR 2 — direct service and idempotency

Commit:

```text
feat(service): add direct notification client and idempotency
```

Goal: let an upstream task worker call one method and receive a normalized result.

Add:

```text
src/notification_service/service.py
src/notification_service/client.py
```

Usage:

```python
client = NotificationClient(provider)
result = await client.send(notification)
```

Behavior:

- Return `accepted`, `failed`, or `unknown`.
- Retry only a provider rejection that is proven to have happened before acceptance.
- Never retry a timeout automatically, because the provider may have accepted the message.
- Reuse an idempotency key to return the existing result.
- Raise `IdempotencyConflict` when the same key is used for different content.
- Keep idempotency storage behind `IdempotencyStore`; the included store is process-local.
- Use `SyncNotificationClient` only from synchronous code outside an active event loop.

The upstream queue must reuse the same idempotency key when its business task retries. A process-local store does not protect duplicates across process restarts; the calling application can provide a shared implementation later without changing `NotificationClient`.
